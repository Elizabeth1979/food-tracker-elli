# Food tracker

A personal Hebrew (RTL) calorie and macro diary: Vite + React + TypeScript, data in Supabase. The owner isn't a developer, so explain changes in plain words. Start with [README.md](README.md): features, setup, and the **Where it runs** table (Vercel project, Supabase project ref, Edge Function, secrets). [NOTES.md](NOTES.md) has what each work session did and what's next; add a short entry at the top when a session ends.

## Commands
- `npm run dev`: the real app on http://localhost:5173. Needs the magic-link email to sign in, which only the owner can open.
- `npm run dev:test`: **test mode** on http://localhost:5174. No sign-in, data in localStorage only, and photos get fixed sample answers, a meal and a multivitamin's label (`src/db.demo.ts`, swapped in by `vite.config.ts`). Use this to click through the UI in the browser pane yourself.
- `npm run build`: type-check and production build. Test mode never ends up in it.
- `npm test`: type-checks and runs `src/*.test.ts` with Node's own test runner (no packages). `src/search.test.ts` holds search ranking and the meal parser to their promises against the real `moh.json`. Vercel runs it before every build (`vercel.json` `buildCommand`), so a failing test blocks the deploy. When a ranking change is meant to change results, update the test in the same commit.
- `npm run test:screens`: the screen test (`e2e/screens.mjs`). Starts test mode itself and clicks through the main flows at phone size with touch: one ＋ (no meal buttons: the meal comes from the time of day, which the test sets with the clock), search and add, photo to review list, "שכחתי משהו?", a new size ("＋ יחידה חדשה…") in that list, a restaurant dish through "זיהוי חכם" (a question, then its ingredients, logged as one line under the dish's name), the meal photo in the diary (open, back up, delete, restore; deleting the meal's last food takes it, undo brings it back, moving the last food to another meal takes it along), diary totals, water by the glass, a supplement from its label (the "תווית" button, check, "עריכה" for the full form; every vitamin, per tablet; none shown while adding; folded in the day and in the food's details), edit an entry's amount and meal, delete and undo, save a meal and re-add it, the usual foods and saved meals one list (most logged first, 10 then "עוד"), moving between days, the back button closing a window and leaving a tab, the foods page, opened from Settings (search first; my foods and saved meals; the database only on search), the guide, a tab in the bar (an article, its sources open in a new tab, back closes it) and its articles linked from the vitamins, the goals and a photo's guessed oil, the goals card and manual-edit warning, tailoring the goals step by step, a weigh-in in Reports that leaves the goals alone, and the weight and waist charts. Not run by Vercel (no browser there); run it before shipping. Needs a Chromium: `npx playwright install chromium`, or set `CHROMIUM_PATH` (in Claude's cloud sessions: `/opt/pw-browsers/chromium-*/chrome-linux64/chrome`). When a change alters a flow, update the test in the same commit.
- `node <script>.ts` can import `src/search.ts` directly (it has no data-layer imports) to check search ranking or the meal parser against `public/foods/moh.json`.
- `.claude/launch.json` has preview configs for all three: dev, test mode, built app.

## How we build (the owner's standards)
- **W3C first.** Semantic HTML (real `<button>`, `<dialog>`, headings, landmarks, `<label>`s), WCAG 2.2 AA: every control has a unique accessible name, text contrast ≥ 4.5:1, touch targets ≥ 44px, visible focus, nothing conveyed by color alone, status changes announced (`role="status"`), RTL with logical properties (`margin-inline-start`, not `margin-left`).
- **DRY and clean code.** One component or helper per idea (e.g. `MealSeg`, `PhotoPick`); search for an existing one before writing a new one. Small functions, names that say what they do, comments only for the why.
- **CSS through the cascade.** Colors, sizes, radii and spacing are custom properties on `:root` (dark mode redefines the same tokens, nothing else). Style elements and a few shared classes; reuse before adding; no inline styles and no one-off classes for a single use; no `!important`.
- **Every bug the owner reports gets a test** that reproduces it, in the same commit as the fix (break the fix once and see the test fail).
- **Tests check behavior, not markup.** Find elements by role and visible/accessible name, never CSS classes, so a redesign that keeps behavior keeps the tests green. When adding a test, break the feature on purpose once and see it fail.

## Deploying
Push to `main` and Vercel deploys production by itself, in about a minute. The home-screen app notices the new build through `/version.json` and reloads (`src/update.ts`).

**Ship without asking (the owner's standing rule).** For changes to the app, commit, push, open the PR, merge it and deploy it yourself once all of these hold: `npm test`, `npm run test:screens` and `npm run build` pass, and you clicked the change through in test mode (`npm run dev:test`) at phone size with touch taps. Then tell the owner, in plain words, that it's live and what changed. If something turns out wrong, roll back (Vercel: promote the previous production deployment) and tell them.
**Still ask first** for: database changes (schema, migrations, editing or deleting stored rows), anything that costs money or changes a paid service (the photo AI model, Supabase/Vercel plans, secrets), and deleting anything.

**After merging to `main`, start the production deploy yourself; don't wait for Vercel's GitHub hook** (the owner's standing request: Vercel has picked up merges 15+ minutes late or not at all). With the Vercel tools: create a deployment with `target: "production"` and `gitSource` `{type: "github", org: "Elizabeth1979", repo: "food-tracker-elli", ref: "main", sha: <merge commit>}` in project `prj_GF3n2aiehutDd5I6h01bhCICGhJz`, team `team_IluAXBY7tqQpBwOf1hRuqt6a`. It builds in under a minute and takes over `food-tracker-nine-khaki.vercel.app`; check it reaches READY and tell the owner it's live. **A late hook build of an older commit can take the domain back** (it happened on 2026-10-21: #10's late build replaced #11 for a few minutes). So about 20 minutes later, check which commit `food-tracker-nine-khaki.vercel.app` serves (get the deployment by that hostname); if it isn't the latest `main`, deploy `main` again. The lasting fix is reconnecting GitHub in the Vercel project settings, which only the owner can do.

## Things to know
- **Research goes in [docs/research.md](docs/research.md)**: each study or source we use, what it found, and what we changed because of it (newest first, with links). The in-app guide ("מדריך", Markdown in `src/articles/`, read by `src/guide.ts`) is for users: Hebrew, about a 2-minute read, tied to what the app does, ending in "מקורות" with primary sources and one "לא ייעוץ רפואי" line; `src/guide.test.ts` holds every article to that.
- Calories always come from the food database (`moh.json` plus the user's own `foods` rows). A meal photo (or a "זיהוי חכם" description) only names foods and guesses amounts, asks a question where it matters, then picks each food's entry from candidates the app's search sends (`mode: 'pick'`), or breaks a dish the database lacks into ingredients; if that fails, the search's own matches stand. The one exception is label scanning (`mode: 'label'`, the new-food form's "צלם טבלת ערכים"): it fills a new food from a package's nutrition table, and the user checks it before saving.
- MoH foods are never copied into the database. A `foods` row with the same id overrides one; that is how edits, added units and "hidden" work.
- Offline (`src/db.ts`): lists are kept in localStorage per user, and writes made offline queue in `pending` and are replayed in order by `syncPending` (on start, `online`, and when the app comes back to the front). While anything is queued, new writes queue behind it. Ids are made on the device, so a replayed create keeps its id, and a duplicate (23505) counts as sent. A request with status 0 means no answer; anything Supabase refuses still throws. Offline, `main.tsx` keeps the last signed-in user instead of showing Login. `App` shows a "waiting to send" line while `hasPending()` (it listens for `pending-changed`) and fetches the past 7 days on start and on `online`, so they're kept for offline.
- Security headers live in `vercel.json`. A new outside origin (API, font, image) means widening the CSP on purpose. Camera is left out of Permissions-Policy so photo capture keeps working.
- Schema changes: update `supabase/schema.sql` too, and record the migration name in the README table.
- The `meal-photo` function code lives in `supabase/functions/meal-photo/`. Redeploy it after changes; it reads `ANTHROPIC_API_KEY` and optional `MEAL_PHOTO_MODEL`.
